# 简单建模与发布

日常只需：找到表 → 用于建模 → 勾选字段 → 检查并确认。

## 找到需要的数据表

打开“Opcenter 数据模型”，系统自动打开最新保存的结构；首次使用读取项目标准 CSV 并保存。平时浏览使用已保存的说明，不要求源数据库在线。

搜索表名或说明，点击表查看关联图、关联列表和完整字段。关联图展示当前表的相邻表，最多 60 张；显示在图上不代表已经加入模型。页面按表去重显示已用于建模的数量，来源草稿及发布工作区中的表均计入；它不等同于已发布数量。状态读取失败时显示待核实。

点击“用于建模”，或勾选多张表一起加入。系统自动保存并进入业务模型。重新加入同一结构版本中的表不会覆盖已保存的设计。

更新结构、刷新数据库说明、打开其他结构版本和 CSV 导入收在“数据来源与更新”。密码仅从环境配置读取。两个项目标准 CSV 不会被修改。

## 编辑业务对象

在“制造语义模型 → 编辑业务对象”中点击编辑：

1. 选择“普通业务对象”或“需要转换（历史记录等）”。
2. 填写业务名称和一句话说明。
3. 普通对象只需勾选需要分析的字段。外键自动作为关系处理，身份字段保留。未勾选字段不进入本体；原始物理字段仍完整保留。
4. 修改自动保存。保存失败会明确提示，重试成功后再关闭；并发修改会阻止覆盖。
5. 点击“检查这个对象”，查看需要处理的问题、选定字段和将移除的字段。确认后，系统在一个事务内完成权威审阅、同步建模库及更新发布工作区。模型或来源发生变化会要求重新检查。

需要转换的表可以先记录目标和说明，稍后处理。目前不执行 History 事件拆分、多表组合或关系表转换。

关联终点尚未进入发布模型时，检查会要求先完成关联对象，或暂不勾选该关联。必要时可使用高级管理调整复杂关系。

## 查看和发布

“查看模型”展示当前待发布模型。“检查发布”继续执行模型检查、版本确认和发布准备；保存对象不等于发布。实际 Graph Studio 数据发布仍在“数据发布管理”中执行，保留幂等、checkpoint、版本与回滚检查。

来源比较和单独审阅保留在“高级管理”，日常简单建模不需要逐个生成候选、确认权威版本、同步建模库。

## 存储和追溯

PostgreSQL 保存完整物理快照、映射草稿、权威修订、发布工作区和冻结版本。字段用途、身份依据和来源版本随模型保存。历史发布资产不删除。来源语义 JSON 仍用于比较，不代表批准的业务定义。
