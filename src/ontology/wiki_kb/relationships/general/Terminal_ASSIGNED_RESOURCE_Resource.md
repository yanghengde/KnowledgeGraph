## 关系说明

在 Siemens Opcenter (Camstar) MES 中，`Terminal`（终端）是操作员与系统交互的界面载体，通常对应物理位置上的工作站、平板或固定式 PC。`Resource`（资源）则代表实际执行生产活动的设备、工装、夹具、测试仪等。`ASSIGNED_RESOURCE` 关系定义了一个终端默认绑定到哪个资源上，使得在该终端上执行的操作、数据采集、报工等动作自动关联到该资源，而无需操作员每次手动选择。

基数 `MANY_TO_ONE` 的含义是：**多个终端可以指向同一个资源，但一个终端只能指向一个资源**。例如，一台大型加工中心旁边可能同时部署了两个操作站（两个 Terminal），这两个终端都指向同一台加工中心（Resource），以便不同工位的人员都能监控或操作；但反过来，一个终端不可能同时控制两台不同的设备——这符合工厂中“一个操作站对应一台机器”或“多站监控同一机器”的典型布局。这种设计既保证了数据归属的清晰，又提供了柔性部署的可能性。

在通用（无产品线）的 MES 建模中，此关系是构建“人员-终端-资源”运行三角的核心环节，直接影响生产报工、SPC 数据采集、设备状态监控等模块的数据流向。正确配置 `ASSIGNED_RESOURCE` 能避免操作员误选资源导致的批次混乱，并简化日常操作步骤。

## 业务场景

### 何时需要配置此关系？

1. **固定工位一对一场景**：每个操作终端物理上绑定一台设备（如冲压机旁的 PC），必须配置该关系，否则操作员在终端上执行“生产报工”或“开始加工”时会看不到默认的设备，需要手动选择 – 增加错误风险并降低效率。

2. **多终端共享资源场景**：一台大型设备（如 SMT 贴片机、热处理炉）有多个操作面或监控点，需要多个终端同时访问同一资源。此时为每个终端配置同一个 Resource，即可实现数据一致共享，各终端上的操作记录都归属该资源。

3. **移动终端与资源临时绑定**：使用平板或工业 PDA 作为移动终端时，通常希望终端先登录到某个资源（例如“线边工具柜”或“可移动测试台”）。通过系统临时配置此关系（或通过用户界面动态切换），可实现灵活的“一机多用”。

### 通用 (无产品线) 典型示例

**场景**：某电子组装车间，有三个工位分别用于贴片、回流焊和 AOI 检测。每个工位都有一台固定 PC（Terminal）。要求操作员登录后，终端自动对应到该工位的设备。

**配置步骤（Opcenter Admin 界面）**：

1. 进入 **Terminal 维护** 页面，找到工位 1 的 Terminal 对象（例如 `TERMINAL_SMT1`）。
2. 在关联对象区域，找到 `ASSIGNED_RESOURCE` 关系，点击“添加”。
3. 在资源选择对话框中，搜索该工位的设备资源 `RESOURCE_SMT_MACHINE_01`（类型为 Machine）。
4. 保存配置。
5. 同理，为其他两个终端分别配置对应的 AOI 设备 `RESOURCE_AOI_INSPECTOR` 和回流焊炉 `RESOURCE_REFLOW_OVEN`。

完成后，当操作员在 `TERMINAL_SMT1` 上打开 MES 客户端并执行“开始生产”事务时，系统会自动填充资源字段为 `RESOURCE_SMT_MACHINE_01`，操作员只需确认或扫描物料条码即可继续。

## 配置要点

- **基数校验**：一个终端只能关联一个资源，若试图关联多个资源，系统会报错。请确保在设计和迁移中不出现重复关联。
- **资源类型限制**：Opcenter 默认允许终端关联任意 Resource 子类型（Machine、Tool、Fixture、TestEquipment 等），但业务实践中应统一规范，例如仅关联 Machine 或 Tool 类，避免混淆。
- **多终端同资源时的数据冲突风险**：多个终端同时指向同一资源时，若两个终端几乎同时执行“开始加工”等改变状态的操作，可能产生并发冲突。建议在业务流程设计中增加资源状态锁定机制（如 check-in/out），或只在读取场景（如数据查看）下使用多终端。
- **终端关联的默认值与运行时切换**：`ASSIGNED_RESOURCE` 设定后，终端登录时默认生效，但 Opcenter 客户端允许操作员在事务中手动修改资源。如需严格锁定（如合规要求），应通过建模时设置 `Resource` 字段为只读或隐藏来实现。
- **配置变更影响**：修改已在使用中的终端关联资源会立即生效。对于正在进行的生产操作（如已开始但未完成报工），新关联关系不会影响已记录的数据，但后续新建的事务将采用新资源。
- **与 Resource 可用性联动**：终端关联的资源若处于“停机”或“维护”状态，Opcenter 通常不会自动阻止终端操作，需要业务规则或事件订阅来触发提示。建议结合 Resource 状态模型二次开发。
- **批量迁移场景**：若使用数据迁移工具（如 Excel Import）批量设置，注意内码（OID）或名称的唯一性，以及关系表中 `MANY_TO_ONE` 约束：同一 Resource 可以出现多次（被多个终端引用），但同一 Terminal 不能重复。
- **角色权限**：配置此关系通常需要“建模管理员”或“系统管理员”角色。普通操作员不应有权限修改终端与资源的绑定关系，以免误操作。

## 常见问题 FAQ

**Q: 一个 Terminal 可以同时关联多个 Resource 吗？**  
A: 不可以。此关系基数定义为 `MANY_TO_ONE`，即一个 Terminal 只能拥有一个 `ASSIGNED_RESOURCE`。如需让操作员在一台终端上选择多个资源（例如多机台轮换），建议将资源选择字段设为可选，而不是通过默认固定关系实现。可以通过自定义客户端行为或事务逻辑让操作员临时切换资源，但该切换不会改变终端本身的关系配置。

**Q: 如果我不配置此关系，操作员还能在 Terminal 上工作吗？**  
A: 可以。`ASSIGNED_RESOURCE` 是可选关系。若不配置，终端登录后执行需要资源的操作时，系统会要求操作员手动选择资源。这对于资源不固定或终端临时使用的场景是合理的。但为了减少操作步骤和错误，建议在固定工位上始终配置此关系。

**Q: 配置完此关系后，如何查看终端当前绑定了哪个资源？**  
A: 在 Opcenter Admin 维护页面打开 Terminal 记录，关联对象区域会显示 `ASSIGNED_RESOURCE` 详情。也可以在运行时通过查询 `Terminal` 对象的 `ResourceName` 属性（取决于客户端版本）来获取。如果是定制报表或脚本，可以直接读取 `Terminal_Resource_Assignment` 数据表。
