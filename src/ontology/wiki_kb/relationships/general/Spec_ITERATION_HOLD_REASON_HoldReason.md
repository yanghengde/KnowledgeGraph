## 关系说明

此关系定义了工艺规范（Spec）与冻结原因（HoldReason）之间的关联，用于处理生产过程中因工序迭代/循环次数达到限制而触发的容器自动冻结场景。在 Siemens Opcenter (Camstar) 中，Spec 作为工艺路线的基础单元，可以配置一个“迭代上限”（Iteration Limit），当某个容器（Container）在同一工序被重复处理达到该上限时，系统将自动将该容器转入冻结状态（Hold），并引用此处配置的 HoldReason 作为冻结原因。该关系是 MANY_TO_ONE 的，即多个 Spec 可以引用同一个 HoldReason，但每个 Spec 只能绑定一个 HoldReason。

在通用产品线场景下，此关系适用于任何需要控制重复加工次数以避免过度处理、质量风险或物料损耗的制造环境。例如，在半导体、电子组装或医疗器械生产中，某些返工/重测工序必须限制次数，超过限定次数后产品应被隔离并等待人工裁决。配置此关系后，系统无需额外编写自定义逻辑即可自动执行冻结动作，并记录标准化的原因代码，便于后续追溯与质量控制。

## 业务场景

### 何时需要配置此关系？
- **返工次数管控**：当产线允许对不良品进行有限次数的重工（Rework），超过指定次数后需永久冻结并触发评审流程时，需要在对应的返工 Spec 上配置迭代上限及冻结原因。
- **测试/老化循环限制**：某些产品在老化测试（Burn-in）或功能测试环节中，若连续多次失败，应停止循环并冻结产品，避免浪费资源或产生假性通过。此时需在测试 Spec 上设置迭代次数限制。
- **物料回收/再利用限制**：在物料回收站点，同一批次物料可能被多次回用（例如溶剂再生），超过特定次数后必须冻结并报废，以符合工艺安全规范。

### 通用 (无产品线) 典型示例
**场景**：电子组件装配线中有一道“焊接补修”工序，允许操作员对虚焊点进行最多3次补焊。超过3次后，产品应自动冻结，原因标记为“过量修补-需质检评审”。

**步骤**：
1. 在 Opcenter 建模工具中，创建一个 HoldReason，Code 为“REPAIR_EXCEEDED”，Description 为“焊接补修次数超限”。
2. 创建一个 Spec（例如 Spec_RepairSolder），将“Iteration Limit”（迭代限制）设置为 3。
3. 在 Spec 的“Holds”标签页中，为关系“ITERATION_HOLD_REASON”选择刚刚创建的 HoldReason“REPAIR_EXCEEDED”。
4. 在工序的 Operation 中引用该 Spec，并关联到实际生产步骤。
5. 当操作员在第4次尝试通过该工序扫描容器时，系统自动拒绝处理，将容器置为 Hold 状态，并在 Hold 记录中引用该原因。

## 配置要点

1. **迭代限制（Iteration Limit）**：需在 Spec 的“General”标签页中设置，数值必须为正整数。若不配置或设为0，则不会触发冻结。
2. **HoldReason 必须预先存在**：在配置关系前，需先通过“Hold Reasons”管理界面创建所需的冻结原因，包括 Code、Description、Hold Type 等字段。
3. **基数 MANY_TO_ONE 的含义**：多个 Spec 可共享同一个 HoldReason（例如“多次返工”），便于统一管理。但一个 Spec 只能绑定一个。
4. **生效范围**：此关系仅在容器（Container）级别有效，不影响批次（Batch）或单个组件（Component）的迭代计数。
5. **与业务规则的关系**：若同时存在其他业务规则（例如自定义验证）也会冻结容器，建议统一使用此标准关系，以保持流程一致性。
6. **测试验证**：配置后务必在测试环境中执行循环操作验证：首次通过不冻结，达到上限后自动冻结，并检查 Hold 记录是否正确关联原因。
7. **生命周期影响**：冻结后的容器仍可手动解冻（Unhold），但解冻后再次通过相同工序时，迭代计数器通常不会重置（除非特殊配置）。若需重置，需额外定制逻辑。
8. **本地化与翻译**：HoldReason 的 Code 建议使用简短英文，Description 可提供多语言翻译，确保前端界面显示正确。

## 常见问题 FAQ

**Q: 为什么我配置了 Iteration Limit 和 ITERATION_HOLD_REASON，但容器到达上限后没有自动冻结？**  
A: 请检查以下常见原因：1) Spec 是否被正确分配到 Operation 中；2) 工序是否启用了迭代计数功能（有些站点类型默认不计数）；3) 容器是否已经处于其他 Hold 状态；4) 系统配置中是否启用了“Allow Automatic Hold”权限。另外，验证测试时需确保操作员使用正确的扫描事务（如 Start/Complete Material）。

**Q: 一个 Spec 能否绑定多个 HoldReason？**  
A: 不能。此关系是 MANY_TO_ONE 的，每个 Spec 只能选择一个 HoldReason。如果需要根据不同的超限条件使用不同原因，应创建多个 Spec，每个 Spec 设置不同的迭代上限和原因。

**Q: 迭代次数限制能否基于产品属性动态调整？**  
A: 原生功能中迭代限制是 Spec 上的固定值。若需根据产品型号、批次等属性动态调整，建议通过自定义业务规则在 Process (资源) 层拦截并调用服务修改容器的 HoldReason 或直接触发冻结，但这样会绕过标准关系。更推荐的做法是为不同产品组创建不同的 Spec 并手动关联。

**Q: 解冻后的容器再次通过该工序，迭代计数器是继续累加还是从0开始？**  
A: 默认情况下，容器上的迭代计数器是基于其生命周期内的实时记录，解冻不会重置。这意味着即使解冻后，第四次再通过依然会被冻结。如需重置，需要在解冻操作中编写自定义脚本来删除或重置相关计数记录。

**Q: 此关系是否适用于批次（Batch）或组件（Component）？**  
A: 不适用。迭代冻结机制仅针对容器（Container）级别。对于批次，需考虑使用 Batch 级别的循环限制或另配业务规则。
