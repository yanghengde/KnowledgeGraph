## 关系说明

在 Siemens Opcenter MES（原 Camstar）中，`SamplingPlan`（抽样计划）定义了在指定检验点对物料或成品进行抽样的规则（如抽样频率、样本数量、抽样方法等）。`Spec`（检验规格）则明确了一项或一组检验项目的具体接受标准（如尺寸上限/下限、外观缺陷代码、性能阈值等）。关系 `ASSIGNED_SPEC` 将一个抽样计划与一个检验规格绑定，表示“该抽样计划所生成的检验任务将依照该规格进行判定”。基数 `MANY_TO_ONE` 意味着**多个不同的抽样计划可以指向同一个检验规格**，但一个抽样计划只能关联一个检验规格。

在洗碗机产线场景中，这一关系允许生产团队为相同的检验标准（如“噪音≤45dB”）灵活配置不同的抽样策略。例如：新机型导入阶段采用100%全检抽样计划，量产稳定阶段改为每批次抽检2台的抽样计划，两个计划可以共用同一个噪音规格对象，无需重复定义规格内容。这种设计避免了规格数据的冗余，并确保所有计划始终使用最新的标准。

另外，`SamplingPlan` 本身通常与某个工位（`Resource` 或 `Operation`）或物料类型关联，而 `ASSIGNED_SPEC` 进一步限定了该计划所执行的检验内容。在洗碗机制造过程中，一个抽样计划可能会覆盖多个检验项目（如电器安全、密封性、喷淋覆盖率），但所有项目都归属于同一个 `Spec` 对象（该 `Spec` 可以包含多个 `SpecDetail`）。因此，**一个抽样计划只能对应一个综合检验规格**，但该规格可以包含多个子项。

## 业务场景

### 何时需要配置此关系？

1. **同一检验标准应用于不同抽样层级**  
   例如洗碗机内胆“焊缝疲劳强度”检验规格（Spec：焊缝无裂纹、承受10万次闭合循环）是固定的，但产线在不同阶段使用不同的抽样计划：新品试产时执行“首件+每2小时抽1台”，批量生产时执行“每批次首检+每50台抽1台”。这两个抽样计划都需要关联同一个焊缝强度规格。

2. **规格升级或变更需要统一维护**  
   当洗碗机行业标准更新或客户提出新要求时（如整机能效等级提升），只需修改 `Spec` 对象中的数据，所有关联该规格的抽样计划自动生效，无需逐一调整每个计划。

3. **多线体共用相同检验标准但抽样规则不同**  
   洗碗机产线可能有两条独立的生产线（A线、B线），生产同型号产品。A线因设备老化需要更高频次抽样，B线则采用标准抽样。两条线可各建一个 `SamplingPlan`，但均指向同一个 `Spec`（如“烘干性能：干燥度≥90%”），便于质量统计与回溯。

### 洗碗机产线 典型示例

**场景**：洗碗机“整机能效测试”工位，检验规格为“待机能耗≤0.5W，洗涤能耗≤0.85kWh/cycle”。  
**现有抽样计划**：  
- `SP_Daily_Random`（每日随机抽2台）  
- `SP_First_Article`（每批次首件必抽）  

**操作步骤**（在 Opcenter 建模界面或通过 API/脚本实现）：

1. 进入 **Spec 管理**，创建名为 `Spec_Energy_Efficiency` 的检验规格，添加两个属性：
   - 待机能耗（上限 0.5W，连续型）
   - 洗涤能耗（上限 0.85 kWh/cycle，连续型）

2. 进入 **SamplingPlan 管理**，创建 `SP_Daily_Random`：
   - 抽样方法：定期（每工作日随机）
   - 样本数量：2
   - 关联对象：选择工位 `Station_EnergyTest`
   - **勾选 ASSIGNED_SPEC** → 选择 `Spec_Energy_Efficiency`

3. 创建 `SP_First_Article`：
   - 抽样方法：批次首件
   - 样本数量：1
   - 关联对象：同上工位
   - **ASSIGNED_SPEC** → 同样选择 `Spec_Energy_Efficiency`

4. 保存后，两个抽样计划生成的检验任务将自动引用同一个能效规格进行判定。

**参数说明**：  
- 如果 `Spec_Energy_Efficiency` 后续将“待机能耗”上限修改为 0.3W，则两个抽样计划的检验标准均会更新，无需修改计划本身。

## 配置要点

1. **Spec 必须完整定义所有检验项目的接受标准**，包括数据类型（连续/离散）、上下限、单位、参考标准版本等，否则抽样计划生成的检验任务无法自动判定。

2. **一个 SamplingPlan 只能关联一个 Spec**。如果工位需要执行多组不同类别的检验（如外观 + 电气安全），建议将所有项目合并到一个 Spec 中（通过 SpecDetail 拆分），或配置多个抽样计划分别关联不同 Spec（但需注意抽样执行逻辑是否会重叠）。

3. **控制 Spec 的“修订版本”**：在 Opcenter 中，Spec 对象支持版本管理。配置 ASSIGNED_SPEC 关系时，应指定当前生效的版本。若规格更新，需要发布新版本并重新绑定关系（或使用“自动跟随最新版本”策略，视系统配置而定）。

4. **验证基数一致性**：MANY_TO_ONE 意味着计划数量可以多于规格数量，但不要反过来让一个计划指向多个规格。如果业务需求确实需要“一个计划使用多个规格”，应检查是否可以通过将多个规格合并为一个父规格（Composite Spec）来实现，或者改用多个独立的抽样计划。

5. **注意工位/资源与 Spec 的独立关系**：`SamplingPlan` 通常还关联了执行工位（`Resource`）或物料（`Material`），`ASSIGNED_SPEC` 不替换其他关系，而是作为补充。例如，同一个工位可能有多个抽样计划，每个计划关联不同的 Spec，分别用于不同产品型号。

6. **在批量导入或 API 创建时**，确保使用正确的引用名称或 ID（如 Spec 的 ObjectId 或 Name），避免因大小写或空格导致关系无法建立。

7. **测试验证**：创建关系后，使用 Opcenter 的“检验任务模拟”功能生成一个虚拟工单，确认抽样计划触发的检验页面正确显示该 Spec 下的所有检验项目及标准。

8. **文档记录**：在知识库或配置手册中明确记录每个抽样计划所绑定的 Spec 名称及其版本，便于未来审计与排查。

## 常见问题 FAQ

**Q: 如果我想让一个抽样计划在检验时既参考“外观规格”又参考“功能规格”，应如何配置？**  
A: 需要将两个规格合并为一个“组合规格”（Composite Spec）。在 Opcenter 中，Spec 对象可以包含多个 `SpecDetail`，每个 Detail 代表一个检验项目。建议创建一个名为 `Spec_外观与功能` 的 Spec，在其中添加外观和功能的多个 Detail，然后将抽样计划关联到此组合规格。如果业务要求严格分离，则只能配置两个独立的抽样计划（一个关联外观规格，另一个关联功能规格），但这样检验任务会分成两次执行，可能增加操作复杂度。

**Q: 基数 MANY_TO_ONE 是否意味着我可以将同一个 Spec 分配给多个不同的抽样计划？这样会不会造成数据冲突？**  
A: 不会造成冲突。这是设计允许的典型用法。多个抽样计划共享同一个 Spec，可以保证标准统一，也便于后期维护。唯一的约束是**一个计划只能绑一个 Spec**。从质量追溯角度看，不同计划生成的检验记录都会引用同一个 Spec 对象，因此统计合格率时非常清晰。

**Q: 当 Spec 发生变更（如放宽标准）后，已分配给计划的旧关系会自动更新吗？**  
A: 取决于 Opcenter 的版本和配置。如果 `ASSIGNED_SPEC` 关系是直接引用 Spec 对象（而非某个固定版本），且 Spec 修改时未创建新版本（默认更新原对象），则所有关联计划会立即生效。但建议每次规格变更都创建新版本，并手动更新抽样计划的关系（或者通过工作流自动切换），以确保历史数据不被污染。请查阅您的 Opcenter 版本关于“规格版本控制”的文档。
