## 关系说明

在 Siemens Opcenter (Camstar) MES 中，`Factory --[REQUIRES_TRAINING_GROUP]--> Skill` 表示一个工厂（Factory）设定一个必须的技能组（Skill）作为该工厂所有操作人员的基础资格要求。基数 MANY_TO_ONE 意味着多个工厂可以共享同一个技能组定义，但每个工厂只能关联一个技能组。这个技能组是一个逻辑容器，其中可以包含多个具体技能（如操作技能、质量检验技能、安全技能等）。

在洗碗机产线场景下，一个工厂（例如“洗碗机总装一厂”）会定义一个名为“基础操作技能包”的技能组，该组包含诸如“门体装配”、“喷淋臂安装”、“控制板测试”等核心技能。所有在该工厂作业的人员（包括正式工、临时工、返岗人员）必须首先完成这个技能组中的所有技能认证，才能上岗操作。通过此关系，MES 可自动校验操作人员是否具备工厂级准入门槛，防止未授权人员进入产线。同时，当多个洗碗机工厂（如南厂、北厂）采用相同的技能标准时，可以复用同一个 Skill 对象，简化管理维护工作。

## 业务场景

### 何时需要配置此关系？

1. **新工厂投产**  
   当新建一个洗碗机生产工厂（例如“洗碗机湖州工厂”）时，需要为这个工厂设定一个统一的技能组，包含该工厂所有岗位共用的基础技能（如“SOP 阅读”、“防静电操作”、“基础工具使用”），确保所有上岗人员先通过基础认证。

2. **技能标准变更**  
   当公司层面更新了洗碗机生产的通用技能要求（例如新增“智能装配扫码”技能），需要将新的 Skill 对象关联到相关工厂，并取消旧 Skill 的关联。此操作通过修改 `REQUIRES_TRAINING_GROUP` 关系实现，而无需逐岗位调整。

3. **跨厂人员调动**  
   当一名操作工从洗碗机内胆车间调到总装车间时，MES 通过对比目标工厂要求的 Skill 与人员已有 Skill 组，自动判断是否需要补训。如果两个工厂用了同一个 Skill 组，则免于重复培训。

### 洗碗机产线 典型示例

**背景**：洗碗机产线包含“总装车间”和“前处理车间”两个 Factory。公司希望所有车间人员必须通过“安全与基础操作”技能组认证后才能进入任何车间。

**操作步骤**：

1. 在 Opcenter 中创建 Skill 对象，名称设为“安全与基础操作”，并添加具体技能项：
   - 技能1：防静电腕带正确佩戴（测试通过）
   - 技能2：紧急停止按钮操作
   - 技能3：螺钉枪使用规范

2. 分别打开 Factory 对象“总装车间”和“前处理车间”，在 Relationships 页签下找到 `REQUIRES_TRAINING_GROUP`，将其值设置为刚创建的 Skill。

3. 验证：当操作员张三在“总装车间”上岗时，MES 检查其个人技能记录。若发现未完成“安全与基础操作”技能组，系统自动阻止其开始工单，并弹出提示“请先完成工厂基础技能培训”。

**参数设定**：
- Factory 字段：`Name = "总装车间"`
- Skill 字段：`Name = "安全与基础操作"`，`Category = "FactoryMandatory"`
- Relationship 属性：无额外参数，直接关联。

## 配置要点

1. **一个 Factory 只能关联一个 Skill**。如果需要多个技能要求，应将它们合并到一个 Skill 对象中，作为该 Skill 下的子技能进行管理。
2. **Skill 对象可以跨工厂复用**。建议对于标准化的通用技能组，统一命名，避免为每个工厂创建重复的 Skill。
3. **配置前确认 Skill 中已包含所需的具体技能**。若后续需调整，可向 Skill 中添加/移除子技能，所有关联的 Factory 会自动生效。
4. **此关系仅用于工厂级准入检查**，不替代岗位（Work Center）或工序（Operation）级别的技能校验。如果某个工序（如“洗碗机总装 - 门体锁紧”）需要额外专属技能，需在其工序级 Skill 关联中单独设定。
5. **注意 Factory 的生效时间**。新建关系后，已上岗人员不受影响，但新上岗或换岗操作会立即触发校验。建议在非生产高峰期配置，或提前通知培训部门。
6. **基数为 MANY_TO_ONE 时，不要试图给一个 Factory 关联多个 Skill**，否则系统会报错。若确有多个独立技能组需求，可考虑创建父 Skill 组（Group）并在子层级下分组。
7. **清理旧关系**：当工厂不再需要某个技能组时，务必先删除 Relationship 再删除 Skill，避免残留引用导致数据不一致。
8. **结合培训模块**：推荐将 Skill 与培训课程（Training Course）绑定，这样人员完成培训后自动获得技能认证，实现“培训 - 认证 - 上岗”闭环。

## 常见问题 FAQ

**Q: 一个工厂可以关联多个技能组吗？基数不是MANY_TO_ONE吗？**  
A: 不可以。MANY_TO_ONE 的含义是多个 Factory 可以指向同一个 Skill，但每个 Factory 只能拥有一个关联的 Skill。如果需要多个技能分组，建议在 Skill 内部按子目录组织，或重新设计技能层级（例如使用包含关系的 Skill Group）。

**Q: 如果洗碗机工厂的某个技能组需要更新，是直接修改 Skill 还是新建一个 Skill？**  
A: 推荐直接修改原有 Skill 对象（增/删子技能），因为所有已关联的 Factory 会同步更新。新建 Skill 并替换关系会导致历史记录丢失，且需要重新通知所有工厂。

**Q: 如何判断哪些人员已经通过了该工厂 Skill 组的所有技能？**  
A: 在 Opcenter 中可以通过“用户技能矩阵”报表或 API 查询每位员工在指定 Skill 下的技能完成状态。也可以将 Skill 组配置为“合格规则”（Qualification Rule），系统自动实时校验。

**Q: 临时工或外包人员是否需要满足工厂技能组要求？**  
A: 是的。`REQUIRES_TRAINING_GROUP` 是工厂层面的强制要求，无论人员类型（正式、临时、外包），只要该人员在 Factory 下执行工单，系统均会校验。建议在人员入职时同步进行基础技能认证。
