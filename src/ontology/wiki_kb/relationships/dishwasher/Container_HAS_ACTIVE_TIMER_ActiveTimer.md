## 关系说明

在 Siemens Opcenter (Camstar) MES 中，`Container`（产品批次）通过 `HAS_ACTIVE_TIMER` 关系关联到 `ActiveTimer`（活跃计时器），表示该产品批次当前正在执行的时效管控任务。每个容器可以在同一时间点拥有多个活跃计时器（基数 ONE_TO_MANY），例如同时监控烘干时长、泄漏测试等待时间、以及老化测试剩余时间。这些计时器通常用于驱动工艺自动化、触发超时警报或产线暂停，确保产品在严格的时间窗口内完成指定步骤。

在洗碗机产线场景中，时效管控至关重要。洗碗机制造涉及许多对时间敏感的工序：如密封胶固化需要精确的干燥时间、电机磨合需要指定的运行时长、最终性能测试需要在特定水温下持续检测。通过 `HAS_ACTIVE_TIMER` 关系，MES 能够实时跟踪每个产品批次的状态，当计时器超时时触发报警或自动放行，从而避免因人为疏忽导致的品质缺陷。此外，该关系支持多计时器并行运行，适应洗碗机产线复杂的多线程生产节奏（例如同时记录烘箱停留时间和冷却等待时间）。

## 业务场景

### 何时需要配置此关系？

1. **烘干工序中的固化时间管控**  
   洗碗机内胆涂覆密封胶后，需要在特定温湿度环境下固化一定时间（例如 120 分钟）。如果未达到要求时间就进入下一工序，可能导致密封失效。需配置一个 `ActiveTimer` 记录固化剩余时间，并在计时结束时自动触发“固化完成”事件。

2. **泄漏测试前的等待与测试窗口**  
   洗碗机组装完成后，需向腔体注入高压空气并保压 30 秒以检测泄漏。但注入完成后必须等待 5 秒（稳定时间）再开始测量。需要两个 `ActiveTimer`：一个用于等待稳定（倒计时 5 秒），一个用于测试保压（倒计时 30 秒）。只有两个计时器都正常结束，产品才能判定为通过。

3. **电机老化运行时间监控**  
   洗碗机的电机在出厂前需空载运行 15 分钟进行老化测试。产线可能同时存在多个测试工位，每个工位为不同容器。通过 `HAS_ACTIVE_TIMER` 关系，MES 可以知道每个批次的老化剩余时间，当时间到时自动允许该批次移出测试工位。

### 洗碗机产线典型示例

**场景：内胆密封胶固化时效管控**  
假设洗碗机内胆经过涂胶后送入烘箱工位。操作员扫描批次条码，触发固化流程：

- **步骤 1**：系统为当前容器创建一个 `ActiveTimer`，名称为 `CureTime`，初始时长 7200 秒（2 小时）。
- **步骤 2**：计时器开始倒计时，同时检查烘箱温度是否在 55°C～65°C 范围内。若温度超限，计时器暂停。
- **步骤 3**：当计时器剩余时间为 0 时，MES 自动更新该容器状态为“固化完成”，并允许产线放行到下一工位。
- **参数设置**：  
  - Timer Name: `CureTime`  
  - Duration: `7200` (单位：秒)  
  - Timer Type: `Countdown`  
  - Auto-Complete Action: 触发 `Container.SetAttribute` 设置固化状态  
  - 暂停条件：烘箱温度 <55°C 或 >65°C  

**步骤 4**：操作员可在 MES 界面或 HMI 上实时查看剩余时间，若超时未放行（例如因故障），系统生成超时事件通知主管。

## 配置要点

1. **明确 Timer 的类型**：Opcenter 支持倒计时（Countdown）和正计时（Elapsed）两种模式。洗碗机产线通常使用倒计时来表示“还需要多久完成”，便于产线节拍控制。
2. **合理设置暂停/重置规则**：如果某个工艺条件不满足（如温度、压力异常），应配置 Timer 暂停逻辑，避免因环境波动导致错误超时。例如烘干时若开门取件，热量流失，应暂停计时。
3. **避免 Timer 数量过多**：虽然基数支持 ONE_TO_MANY，但每个活跃计时器都会占用系统资源。建议只对关键时间窗口（直接影响品质的步骤）启用，不要为每个简单操作都创建 Timer。
4. **使用 Timer 关联工序事件**：可将 Timer 结束事件绑定到 `Operation.Complete`、`Container.Move` 等系统动作，实现自动化流程。例如 Timer 到零后自动执行放行。
5. **测试环境验证时序**：在开发环境先模拟多计时器并行（如泄漏测试同时进行等待和保压），确保互不干扰，且超时处理逻辑正确。
6. **考虑产线节拍**：Timer 时长设置应结合产线设计节拍（Takt Time），避免因 Timer 过长导致瓶颈，或过短造成误判。可适当增加 5%～10% 的缓冲时间。
7. **处理异常中断**：当产线因故障停机时，Timer 应允许系统管理员手动暂停、重置或延长，以应对异常恢复场景。
8. **数据清洗与历史归档**：产品完工后，`ActiveTimer` 会自动变为非活跃，系统应定期清理历史记录，避免数据库膨胀。建议使用 Opcenter 的数据清理计划。

## 常见问题 FAQ

**Q: 如果一个容器有多个 ActiveTimer，其中一个超时，其他 Timer 会受影响吗？**  
A: 通常每个 Timer 独立运行，不受其他 Timer 状态影响。但您可以配置全局事件：例如当任何一个 Timer 超时时，可触发暂停所有 Timer 或终止流程。默认行为是各自为政。

**Q: Timer 的持续时间单位是什么？可以设置更小的单位（如毫秒）吗？**  
A: Opcenter 中 Timer 的持续时间通常以秒为单位存储（整型），但您可以在显示时转换为分钟或小时。如果生产需要毫秒级精度，建议使用自定义字段或扩大数据范围（例如以毫秒为单位存储整数值，但界面自动换算）。

**Q: 如何查看某个 Container 的所有活跃 Timer？**  
A: 可以在 Opcenter 的 “Container 详情” 页面的 “Tracker” 或 “Timers” 关联视图中查看，或者通过 API 查询：`GET /api/containers/{containerId}/activeTimers`。在 MES 客户端界面上可以定制一个自定义网格展示 Timer 名称、剩余时间、开始时间等信息。

**Q: 如果产线临时需要延长某个 Timer（例如烘干时间不足），如何操作？**  
A: 可在 Opcenter 中为该 Container 的指定 Timer 执行 “Extend” 动作，输入延长的秒数。需要确保操作用户有相应的权限（如 Supervisor 角色）。建议事先在配置中启用 Timer 的 “Allow Extension” 属性。

**Q: 洗碗机产线中，Timer 是否可以与自动化设备（PLC）联动？**  
A: 可以。Opcenter 支持通过 MQTT、REST API 或数据库插件与 PLC 通信。例如当 PLC 检测到烘箱门关闭时，通过 API 触发 Timer Start；当 Timer 到零时，MES 发指令 PLC 点亮绿灯放行。这需要定制开发，但 Opcenter 提供了标准的事件触发点（如 `OnTimerComplete`）可供集成。
