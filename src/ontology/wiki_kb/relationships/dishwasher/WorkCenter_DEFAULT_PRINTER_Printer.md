## 关系说明

在 Siemens Opcenter (Camstar) MES 中，`WorkCenter`（工作中心）与 `Printer`（打印机）之间的 `DEFAULT_PRINTER` 关系用于定义指定工作中心在默认情况下应使用的物理打印设备。当一个工作中心关联了多个打印机时，这一关系确定了“默认”选项，从而简化操作员在打印标签、报告或条码时的选择流程。

在洗碗机产线场景中，每一条装配工位（如内胆组装工位、门体安装工位、包装工位）通常需要频繁打印产品序列号标签、组件追溯标签或包装箱标识。通过为每个工作中心配置唯一的默认打印机，系统可以在触发打印行为时自动发送任务到该设备，无需操作员每次手动选择打印机，从而提升操作效率并减少人为错误。

需要注意的是，`MANY_TO_ONE` 的基数意味着一个 `Printer` 可以被多个 `WorkCenter` 引用为默认打印机，但每个 `WorkCenter` 只能有一个默认打印机。这种设计适合在产线布局中，多个相邻工位共享同一台物理打印机的场景，例如包装区多个工位共用一台工业条码打印机。

## 业务场景

### 何时需要配置此关系？

1. **新产线初始化**：当洗碗机产线新建或重组时，各工作中心（如预装、总装、检验、包装站）需要分配不同的打印任务，必须为其指定默认打印机以确保数据流自动匹配生产区域内的物理设备。

2. **打印机故障或替换**：若某工位的默认打印机损坏或需要维护，需临时将默认打印机切换至备用打印机；或当打印机升级为更高速度型号时，需更新关系以指向新设备。

3. **产线分区管理**：在洗碗机产线的不同功能区（例如塑料件注塑区、金属冲压区、总装区）使用不同类型的打印机（如耐高温标签打印机、高清晰二维码打印机），通过配置默认打印机可避免操作员选错打印介质。

## 配置要点

1. **打印机必须提前在 Opcenter 的 Resource（资源）中注册**：Printer 对象需要先创建并配置正确的网络地址、打印协议和驱动参数，否则 WorkCenter 无法引用。

2. **关系仅限基础建模，不控制复杂逻辑**：DEFAULT_PRINTER 只是提供一个默认值，业务逻辑（如根据不同产品类型选择不同打印机）需要在 Workflow 或 Screen Event 中自行实现。

3. **注意基数约束**：一个 Printer 可以被多个 WorkCenter 引用为默认，但不要意外产生循环依赖（例如工作中心 A 的默认打印机是 B 工作中心的临时打印机），这会影响故障排查。

4. **现场变更后需同步重新部署**：若洗碗机产线内物理打印机的位置发生调整（如将包装区的打印机移至预装区），必须及时更新对应的 WorkCenter 默认关系，避免数据打印到错误区域。

5. **与 Label Template（标签模板）配合使用**：Default Printer 仅决定物理目标设备，而真正打印的标签内容由 Label Template 指定，需确保模板中的字段（如序列号、型号）与洗碗机产品数据正确映射。

6. **批量配置建议使用 Import/Export 工具**：对于含多个工位的大型洗碗机产线，手动逐条配置效率低，可利用 Opcenter 的 Data Transfer 功能导出 CSV 修改后批量导入。

7. **测试环境与生产环境分离**：在开发或测试环境中配置默认打印机时，应使用虚拟打印机或模拟设备，避免误发送真实打印任务。

## 常见问题 FAQ

**Q: 配置了默认打印机后，为什么在某些操作中仍提示选择打印机？**  
A: 可能是该操作（如打印特定类型的报告或临时标签）在 Opcenter 中的逻辑覆盖了默认设置。请检查该打印事件的 Screen Event 或 Action 是否显式要求“提示用户选择打印机”，或是否关联了不同的 Printer 字段。

**Q: 一个工作中心的默认打印机可以随时修改吗？会影响正在进行的生产订单吗？**  
A: 可以修改，且不会影响已经发起的打印任务（已进入打印队列的任务会发送至原打印机）。修改后会立即影响后续所有自动打印操作。建议在换班或生产间隙进行更改。

**Q: 如果默认打印机离线或故障，系统会如何处理？**  
A: Opcenter 默认不会自动回退到其他打印机。打印任务会一直等待打印机响应直至超时。建议在业务逻辑中增加容错机制（如捕获打印失败后提示操作员手动选择备用打印机），或通过监控系统提前预警。
