## 关系说明

在 Siemens Opcenter MES（Camstar）中，`Spec`（规范）定义了某一工序（Operation）需要遵循的具体执行标准、参数、检查项或规则。`ASSIGNED_TO_OPERATION` 关系允许将多个不同的 `Spec` 绑定到同一个 `Operation` 上，从而实现“一处工序，多套规范”的灵活配置。这种设计避免了为每个变体重复创建相同类型的工序，简化了建模和维护。

在洗碗机产线的实际场景中，不同型号（例如标准型、嵌入式、高端蒸汽型）的洗碗机可能需要经过相同的物理工序（如“整机功能测试”），但测试电压、程序代码、水压范围、噪音限值等参数可能完全不同。通过将多个 `Spec` 指向同一个 `Operation`，产线可以共享工序的基础定义（如人机界面、工位配置、数据采集点），而运行时根据产品批次或序列号自动匹配对应的 `Spec`，实现差异化管理。这既保证了工序模板的统一性，又支撑了多品种混线生产的柔性需求。

## 业务场景

### 何时需要配置此关系？

- **同一工序支持多种产品变体**  
  当洗碗机产线生产不同型号（如 A 系列、B 系列）时，虽然它们都经过“内胆气密性测试”这道工序，但测试压力、保压时间、泄漏率上限不同。此时可为该工序创建多个 `Spec`，每个 `Spec` 对应一个产品系列。

- **同一工序根据工艺版本区分规范**  
  新产品导入或工艺优化后，旧版规范可能仍用于返修或低端产品，新版规范用于主线生产。通过将多个版本规范挂接到同一工序，可以灵活切换而无需复制工序对象。

- **同一工序按产线或班次应用不同标准**  
  例如白班和夜班使用不同的检验频率或抽样方案；或者两条并行的测试工位共享同一个 `Operation` 定义，但各自关联不同的 `Spec`（如首件检验 vs 巡检）。

### 洗碗机产线 典型示例

**示例：整机噪音测试工序（Operation: Noise_Test_Station）**  

- **规范1：标准型洗碗机噪音规范**  
  - 测试环境噪音 ≤ 35dB  
  - 运行程序：标准洗涤 60°C  
  - 产品最大噪音 ≤ 48dB  
  - 采样点：前门中心、左侧板  

- **规范2：高端静音型洗碗机噪音规范**  
  - 测试环境噪音 ≤ 30dB  
  - 运行程序：节能洗 50°C  
  - 产品最大噪音 ≤ 42dB  
  - 采样点：前门中心、左右侧板、顶部面板  

- **规范3：返修品噪音快速检测规范**  
  - 仅运行空载 5 分钟  
  - 产品最大噪音 ≤ 50dB  
  - 无需记录环境噪音  

配置步骤：
1. 创建 Operation `Noise_Test_Station`，设置工位属性（如测试设备连接、数据采集模板）。
2. 分别创建三个 Spec：`Noise_Spec_Standard`、`Noise_Spec_Silent`、`Noise_Spec_Rework`，其测试参数、限值、数据字段不同。
3. 为每个 Spec 设置 `ASSIGNED_TO_OPERATION` 关系指向 `Noise_Test_Station`。
4. 在产品工艺路线中，该 `Operation` 被单次引用，但 MES 运行时通过产品属性（如型号、工单类型）自动查找并应用对应 Spec。

## 配置要点

1. **Spec 名称需具有业务语义**，建议包含产品系列、版本或用途标识（如 `Noise_Spec_Standard_v2`），避免与操作名称重复。
2. **一个 Operation 可关联的 Spec 数量**受 Opcenter 系统限制（通常无硬性上限），但过多会影响选择性能，建议按需控制（一般不超过 20 个）。
3. **Spec 之间的差异字段**应尽量保持结构一致（相同的数据采集点名称），以便统一报表分析。若差异太大，可考虑拆分 Operation。
4. **激活状态管理**：当需要淘汰旧规范时，可在 Spec 上设置有效期或状态字段，或在工艺路线中通过规则动态切换，而不是直接删除 Spec，以保证历史追溯。
5. **若使用产品路由（Product Routing）**，需确保 `Spec` 的匹配逻辑与路由选择逻辑一致（例如基于产品类型、物料版本、工单属性）。
6. **注意 Spec 的继承关系**：如果 Spec 本身有父规范（Parent Spec），则父规范必须与 Operation 的匹配规则兼容（通常仅使用最末级 Spec）。
7. **在 Opcenter 中创建此关系时**，建议先在 `Spec` 对象上设定 `Operation` 属性，再在 `Operation` 对象上确认关联列表，避免双向不一致。
8. **测试验证**：在量产前模拟不同产品通过同一工序，确认 MES 能正确调用对应的 Spec，并正确记录规范版本到历史数据中。

## 常见问题 FAQ

**Q: 如果同一个工序关联了多个 Spec，MES 如何知道该用哪一个？**  
A: Opcenter 通过解析产品/工单/批次上的“规范选择规则”来匹配。常见方式包括：(1) 基于产品类型或序列号匹配；(2) 基于工单的“规范选择器”属性；(3) 通过工作流脚本动态获取。您需要在 `Workflow` 或 `Data Collection` 中配置规则表达式。

**Q: 如果我想为同一个工序的某个 Spec 增加一个新数据采集字段，会影响其他 Spec 吗？**  
A: 不会。每个 `Spec` 独立定义其数据收集模板。新增字段只需修改对应 Spec 的 `Data Collection Definition`，其他 Spec 不受影响。但需要注意，工序本身的数据收集模板是通用的，Spec 中的字段应预先在工序模板中定义好，否则运行时可能无法显示。

**Q: 一个 Spec 能否同时分配给多个 Operation？**  
A: 不能。本关系 `ASSIGNED_TO_OPERATION` 是 MANY_TO_ONE，即一个 Spec 只能指向一个 Operation。如果需要同一套规范应用于不同工序，应复制 Spec 并分别分配，或使用父 Spec 机制（但父 Spec 不直接绑定 Operation）。
