## 关系说明

在 Siemens Opcenter (Camstar) MES 中，`Container --[PACKED_INTO]--> Box` 关系用于描述一个 **批次（Container）** 被装入一个 **箱子（Box）** 的物理包装过程。基数 `MANY_TO_ONE` 表示多个批次（或多个单独的物理容器）可以被包装到同一个箱子中，而一个箱子可以包含来自不同批次的产品，但每个批次最终只属于一个箱子（即箱子是更上层的包装单位）。  

在储能系统 (ESS) 装配线场景中，此关系主要应用于 **模组 (Module) 和电池簇 (Rack) 的出厂包装** 以及 **产线内部转运包装**。例如，经过测试合格的电池模组会被装入专用的模组包装箱（Box）中，一个包装箱可容纳多个模组；同样，完成总装的电池簇在发货前也会被装入木箱或铁箱中。此关系还用于追溯：通过箱子编号可反查内部所有批次的产品信息（生产日期、测试数据、BMS 版本等），从而满足储能行业对物料可追溯性的严格要求。  

此外，在 ESS 产线中，`PACKED_INTO` 关系也用于 **BMS 软件烧录后的包装验证**。每个模组的 BMS 地址、高压连接器和通讯线束在包装过程中需与箱内唯一槽位绑定，确保后续整机测试时能够准确识别每个模组的状态。因此，该关系不仅是一个物理包装定义，更是质量追溯链路中的关键环节。

## 业务场景

### 何时需要配置此关系？

1. **模组成品包装**  
   当装配线完成电池模组的最终测试（如 OCV、ACIR、BMS 通讯校验）后，需要将多个模组装入标准包装箱（Box），每箱通常固定数量（如 12 个或 16 个），用于后续的仓储、转运或发货。在此步骤中，必须通过 `PACKED_INTO` 关系将每个模组批次（Container）与包装箱批次（Box）关联。

2. **电池簇发货前组装**  
   电池簇（Rack）由多个模组、高压线束、BMS 控制盒等组成，在完成整机测试（绝缘耐压、充放电性能、BMS 系统功能）后，需要将整个簇装入定制化铁箱或木箱中。此时，电池簇本身作为一个 Container，被 `PACKED_INTO` 一个发货箱（Box）。一个发货箱内通常只装一个电池簇（因为体积较大），但也可能包含附属零件盒。

3. **返修/拆包重工**  
   当发现已包装的模组或电池簇存在缺陷时，需要从箱子中取出对应的 Container 进行维修。此时必须正确维护 `PACKED_INTO` 关系（解除关联），并在维修完成后重新执行包装操作。这种情况下，箱子可能处于“部分满箱”状态，MES 需支持动态调整包内 Container 数量。

### 储能系统(ESS)装配线 典型示例

**场景：48V 15kWh 电池模组包装入标准运输箱**  

- **背景**：每个标准运输箱（Box）最多可容纳 16 个同型号模组。模组包装线采用自动扫码枪扫描模组序列号与箱号绑定。  
- **操作步骤**：  
  1. 操作员在 Opcenter 客户端选择“包装”作业，扫描箱号（Box ID），系统创建一个新的 Box 对象。  
  2. 依次扫描已测试合格的模组批次（Container ID），每次扫描后系统检查该模组是否已绑定其他 Box（防止重复包装）。  
  3. 当扫描满 16 个模组后，系统自动关闭箱号，并写入 `PACKED_INTO` 关系（每个 Container 指向同一个 Box）。  
  4. 打印箱标签（包含箱号、箱内模组序列号清单、生产日期、质检结果）。  
  5. 如果包装过程中发现某个模组测试数据异常，系统可拒绝包装，并提示操作员移出。  
- **关键参数**：  
  - `Container` 类型：`ModuleLot`  
  - `Box` 类型：`ShippingBox`  
  - 最大容量：16  
  - 包装规则：必须按 “ModuleLot → ShippingBox” 单向关系  
  - 检验规则：所有被包装的模组必须处于 “Test Passed” 状态  

## 配置要点

1. **对象类型定义**：在 Opcenter 建模中，需要明确 `Container` 和 `Box` 的 Object Type。建议将 `Container` 设为 `ModuleLot` 或 `RackLot`，`Box` 设为 `ShippingBox` 或 `PackagingBox`。需配置 `PACKED_INTO` 关系的起点和终点类型。  

2. **基数约束**：基数 `MANY_TO_ONE` 意味着一个 Box 可以关联多个 Container，但一个 Container 只能关联一个 Box。配置时需在 Relationship 属性中设置 `MaxCardinality` 为 `N:1`，并添加业务规则防止同一 Container 被分配到多个 Box。  

3. **容量限制**：在 Box 对象上可添加自定义 Attribute（如 `MaxContainerCount`）用于配置箱子的最大装载数量，并在包装操作中开发验证逻辑，超出后阻止新增 Container。对于电池簇，通常设置为 1。  

4. **序列化与追溯**：`PACKED_INTO` 关系的数据必须包含时间戳、操作员、工站等元数据，确保能追溯谁在何时将哪些模组装箱。建议在 Box 上存储 `ContainerList`（逗号分隔或 XML）以加速查询。  

5. **包装状态机**：设置 Box 的生命周期状态（如 `Empty`、`Partial`、`Full`、`Sealed`）。当关系数量达到最大容量时，自动将 Box 状态置为 `Full`；若从满箱中移出 Container，则状态回退为 `Partial`。  

6. **BMS 系统集成**：如果模组在装入 Box 时需要绑定 BMS 地址（如 CAN ID），则应在包装过程中触发与 BMS 系统的接口，将箱号与模组 BMS 映射关系写入数据库中，以支持整机测试时自动识别。  

7. **异常处理**：配置包装操作的回滚逻辑（例如包装后立即质检发现不良，需能从 Box 中移除该 Container）。移除时应自动更新 Box 状态和容量计数，并保留历史关系（如 `WasPackedIn`）用于审计。  

8. **多层级包装**：如果存在 “模组 → 托盘 → 箱” 的多层包装，建议拆分多个 `PACKED_INTO` 关系（如 `Container → Tray` 和 `Tray → Box`），或使用 `PackageStructure` 对象，避免在单层关系中混淆。  

## 常见问题 FAQ

**Q: 一个箱子可以同时包含不同批次的模组吗？**  
A: 可以。在 Opcenter 中，只要 `Container` 类型匹配（如都是 `ModuleLot`），不同批次的模组（甚至不同生产日期）可以被装入同一个 `Box`，但需要注意客户或法规可能要求同箱内物料生产批次一致。建议通过业务规则校验或属性约束来实现。

**Q: 如果包装后发现某个模组有质量问题需要拆箱，如何处理？**  
A: 需要执行“解包装”操作：在 Opcenter 中通过 `Unpack` 事务解除该 Container 与 Box 的 `PACKED_INTO` 关系。系统会自动更新 Box 的容量计数和状态（若满箱变成 Partial）。为保留追溯，建议保留关系的历史记录（如 `PackedFrom` 反向关系），并在 Box 上标记“该箱曾被装过 XX 模组但已移除”。

**Q: 在电池簇包装时，一个簇就是一个 Container，为什么还需要 Box？**  
A: 虽然电池簇体积较大，但出于运输保护和海关要求，仍需将其装入特定规格的木质或铁质包装箱中（Box）。在 MES 中，将簇视作 Container 并 `PACKED_INTO` Box 可以记录箱的唯一编号，方便物流扫描、关联运输单据，并支持将来对箱内附带的配件（如备件包）进行管理。同时，通过此关系可以追踪簇的最终装箱位置和状态。
